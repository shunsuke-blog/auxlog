## 残っていること

### A. アプリ（auxlog-mobile）側の修正 — 次のチャットの本題。ここが出そろってから iOS のビルド
1. **履歴に「トレーナーが記録」「トレーナーが修正」を出す**（Web の components/history/SessionList.tsx と同じ）。GET /api/sessions は `*` で recorded_by_trainer_id・edited_by_trainer_id をもう返している。トレーナーが入力しただけの日は疲労度を出さない。
2. **ログイン用リンクの第2段階**（docs/handoff_2026-10-29.md の「残っていること」2 の内容）
   - Universal Links（auxlog.app の apple-app-site-association と、アプリの associatedDomains）とアプリ側の /join の受け口。
   - 誘導の形はオーナー了承済み: 未インストールなら Web が開く。「ようこそ」の画面に「このまま始める（ブラウザ）」「アプリで始める（App Store → 入れたらもう一度リンクを押す）」。遅延ディープリンクはやらない。先にブラウザで始めた人は、ブラウザの画面の「アプリで開く」でその場でアプリ用の使い捨てリンクを作って移る。
   - リンクで作ったアカウントは今アプリにログインできない（Apple・Google・メールが無い）ので、これが無いとアプリで使えない。
3. **アプリの古い画面**: 招待コードの入力（src/app/invite.tsx）を受け取り方の案内に、設定のアカウント（account.tsx）で仮のメール（client-<uuid>@clients.auxlog.app）を出さない。
4. ほかにアプリ側で直したいものが無いか、オーナーと洗い出してからビルドする。master には未リリースの変更（ログイン画面の整理、有酸素、それ以前の分）が溜まっている。
5. ビルド後に実機で確認: LINE から開いた時にアプリが直接開くか（今の Web はいつものブラウザで開く設定 ?openExternalBrowser=1）。

## 注意（今回わかったこと）

- **クライアントの記録に触る画面は自動保存にしない**（オーナー指示 10/30）。保存ボタンをなくす方針（開発の絶対条件）はテンプレート編集などトレーナー自身のデータの話で、クライアントの記録は明示的に保存する。
- ブラウザの操作ツールが途中で切れると、手元ではトレーナーとしてログインできない（service_role のキーが無く、パスワードも無い）。画面の確認はオーナーにお願いする。DB の関数は `supabase db query --linked` で `set local role authenticated` と `request.jwt.claims` を使い、トランザクションの中で試して rollback する（scratchpad に試しの SQL を作って -f で流した）。
- 引き続き、~/dev/auxlog は複数のチャットが同じフォルダで作業している。コミットの前に `git status` で自分のファイルだけを add し、`git diff --cached --stat` で確かめる。push すると別のチャットの未 push のコミットも一緒に出る。
